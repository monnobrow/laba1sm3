# Лабораторная работа №1. Абстрактные структуры данных

Реализация базовых структур данных на C++ и Go с интерфейсом в стиле простой СУБД. Данные лежат в файле `data.json`, каждая команда выполняется отдельным запуском программы:

```bash
./dbms --file data.json --query 'SPUSH mystack item'
```

Вариант 2: дерево — **АВЛ-дерево** (сбалансированное двоичное дерево поиска).

## Возможности

- Массив, односвязный и двусвязный списки, очередь, стек, АВЛ-дерево.
- Хранение в JSON: файл читается при запуске и перезаписывается только при изменении данных.
- Сколько угодно структур в одном файле. Структура определяется типом и именем (`s1`, `s2`, `mystack`…).
- Операции «до/после значения» ищут узел внутри самой структуры за один проход.
- Pop сразу возвращает снятое значение.
- Значения — строки, в том числе с пробелами и кириллицей. Дерево хранит целые числа.
- Без контейнеров стандартной библиотеки и без JSON-библиотек: парсер написан вручную.
- Версия на Go с теми же командами и тем же форматом файла (без деревьев).

## Сборка

C++ (все структуры, включая дерево):

```bash
g++ -std=c++17 -o dbms main.cpp commands.cpp json.cpp struct_cplas/*.cpp
```

Go (линейные структуры, деревья по заданию только на C++):

```bash
cd struct_go && go build -o dbms/dbms ./dbms
```

## Запуск

```bash
./dbms --file data.json --query 'КОМАНДА имя [аргументы]'
```

- `--file` — файл с данными. Если его нет, он создаётся при первом изменении.
- `--query` — команда в кавычках. Значение с пробелами пишется в двойных кавычках: `SPUSH s "hello world"`.

Результат печатается после `->`, ошибка — `Ошибка: …`. `HELP` выводит список команд.

```
$ ./dbms --file data.json --query 'SPUSH s1 a'
-> a
$ ./dbms --file data.json --query 'SPUSH s1 "hello world"'
-> hello world
$ ./dbms --file data.json --query 'PRINT s1'
Стек s1 (с вершины):
hello world
a
$ ./dbms --file data.json --query 'SPOP s2'
Ошибка: стек пуст
$ ./dbms --file data.json --query 'ISMEMBER t 27'
-> TRUE
```

## Команды

### Массив

| Команда | Действие |
|---|---|
| `MPUSH a x` | добавить в конец |
| `MINSERT a i x` | вставить по индексу |
| `MGET a i` | получить по индексу |
| `MSET a i x` | заменить по индексу |
| `MDEL a i` | удалить по индексу |
| `MLEN a` | длина |

### Односвязный (`F`) и двусвязный (`L`) списки

| Команда | Действие |
|---|---|
| `FPUSH f x` / `FPUSH f TAIL x` | добавить в конец |
| `FPUSH f HEAD x` | добавить в начало |
| `FPUSH f AFTER t x` | добавить после первого узла со значением `t` |
| `FPUSH f BEFORE t x` | добавить перед первым узлом со значением `t` |
| `FPUSH f INDEX i x` | вставить по индексу |
| `FDEL f HEAD` / `FDEL f TAIL` | удалить из начала / из конца |
| `FDEL f AFTER t` / `FDEL f BEFORE t` | удалить узел после / перед `t` |
| `FDEL f VALUE x` | удалить по значению |
| `FDEL f INDEX i` | удалить по индексу |
| `FGET f i` | получить по индексу |
| `FFIND f x` | поиск по значению (`TRUE` / `FALSE`) |
| `FPRINTBACK f` | вывести от хвоста к голове |

Для двусвязного списка те же команды с буквой `L`: `LPUSH`, `LDEL`, `LGET`, `LFIND`, `LPRINTBACK`.

### Очередь и стек

| Команда | Действие |
|---|---|
| `QPUSH q x` / `QPOP q` | положить в хвост / снять из головы |
| `SPUSH s x` / `SPOP s` | положить / снять с вершины |

### АВЛ-дерево

| Команда | Действие |
|---|---|
| `TINSERT t x` | добавить |
| `TDEL t x` | удалить |
| `TGET t x` / `ISMEMBER t x` | поиск (`TRUE` / `FALSE`) |
| `TPRINT t PRE\|IN\|POST\|BFS` | обход: прямой, симметричный, обратный, в ширину |

### Общие

| Команда | Действие |
|---|---|
| `PRINT имя` | вывести все структуры с этим именем |
| `HELP` | список команд |

## Формат data.json

```json
{
    "massiv": {
        "arr": ["x"]
    },
    "spisok1": {
        "f": ["0", "1", "2"]
    },
    "ochered": {
        "q": ["2"]
    },
    "stack": {
        "s1": ["a", "hello world"],
        "s2": []
    },
    "tree": {
        "t": [25, 20, 27]
    }
}
```

Уровни: тип структуры → имя → значения. Типы: `massiv`, `spisok1`, `spisok2`, `ochered`, `stack`, `tree`.

- Структура создаётся при первом добавлении. Структур одного типа может быть сколько угодно, команда меняет только ту, чьё имя указано.
- Одно имя может быть у структур разных типов: стек `same` и дерево `same` — разные структуры.
- Списки и очередь записываются от головы к хвосту, стек — от дна к вершине.
- Дерево записывается обходом в ширину. Если вставлять узлы в этом порядке, получается то же самое дерево без поворотов.
- Строки экранируются (`\"`, `\\`, `\n`). При чтении понимается и `\uXXXX`, поэтому читается и файл, записанный другой программой.
- Если файл повреждён, программа сообщает об ошибке и не трогает его.

C++ и Go работают с одним и тем же файлом. Go не изменяет дерево, записанное C++.

## Особенности реализации

**Поиск внутри структуры.** Операции «после/перед значения» принимают значение `target` и находят узел сами, за один проход, без отдельного поиска в слое команд:

- `FAddAfter(head, target, x)`, `FAddBefore(head, target, x)`, `FDeleteAfter(head, target)`, `FDeleteBefore(head, target)`, `FDeleteValue(head, x)` и те же операции у двусвязного списка;
- в односвязном списке вставка «перед» идёт на шаг позади, а удаление «перед» — на два шага. Поэтому предыдущий узел не нужно искать вторым проходом;
- у двусвязного списка после одного поиска перевязка делается за O(1) через `prev` / `next`;
- `TAdd` и `TDelete` сами находят место в дереве и сообщают, если число уже есть или его нет.

**Функции структур — `void`.** Проверки (target не найден, структура пуста, нет такого индекса) делает сама функция и печатает результат: `-> x` или `Ошибка: …`. Слой команд только разбирает аргументы и вызывает функцию.

**Pop возвращает значение.** `string SPop(Stack&)` и `string Q1Pop(Queue1*)` снимают элемент и сразу отдают его. Отдельный `STop` перед `SPop` не нужен.

**Сохранение.** `main` сравнивает значения структуры до и после команды и перезаписывает `data.json`, только если они изменились. Неудачная команда не создаёт в файле пустую структуру.

**В памяти строится только нужная структура.** Файл загружается как набор записей «тип + имя + значения». Настоящий стек, список или дерево строится только для структуры из запроса.

## АВЛ-дерево

В каждом узле хранится высота поддерева `height`. Баланс узла — разность высот левого и правого поддеревьев, он должен быть от −1 до 1. После вставки и удаления на обратном ходе рекурсии вызывается `TBalance`:

| Случай | Условие | Действие |
|---|---|---|
| LL | баланс > 1, у левого сына ≥ 0 | правый поворот |
| LR | баланс > 1, у левого сына < 0 | левый поворот у сына, затем правый |
| RR | баланс < −1, у правого сына ≤ 0 | левый поворот |
| RL | баланс < −1, у правого сына > 0 | правый поворот у сына, затем левый |

Удаление: лист или узел с одним сыном заменяется сыном. У узла с двумя сыновьями `TDeleteMin` вырезает минимум правого поддерева, и он встаёт на место удаляемого значения.

По сравнению с красно-чёрным деревом АВЛ сбалансировано строже: высота не больше 1.44·log n против 2·log n, поэтому поиск быстрее. Зато при удалении может понадобиться до O(log n) поворотов, а у красно-чёрного — не больше трёх.

## Сложность операций

| Операция | Массив | Односвязный | Двусвязный | Очередь | Стек | АВЛ-дерево |
|---|---|---|---|---|---|---|
| Добавить в конец / push | O(1)\* | O(n) | O(1) | O(1) | O(1) | — |
| Добавить в начало | O(n) | O(1) | O(1) | — | — | — |
| Добавить по индексу | O(n) | O(n) | O(n) | — | — | — |
| Добавить после / перед значением | — | O(n) | O(n) | — | — | — |
| Вставка в дерево | — | — | — | — | — | O(log n) |
| Удалить из начала / pop | O(n) | O(1) | O(1) | O(1) | O(1) | — |
| Удалить из конца | O(1) | O(n) | O(1) | — | — | — |
| Удалить по индексу | O(n) | O(n) | O(n) | — | — | — |
| Удалить после / перед значением | — | O(n) | O(n) | — | — | — |
| Удалить по значению | O(n) | O(n) | O(n) | — | — | O(log n) |
| Доступ по индексу | O(1) | O(n) | O(n) | — | — | — |
| Поиск по значению | O(n) | O(n) | O(n) | O(n) | O(n) | O(log n) |
| Вывод всей структуры | O(n) | O(n) | O(n) | O(n) | O(n) | O(n) |

\* В среднем: при заполнении ёмкость удваивается с копированием за O(n), но редко.

- **Массив.** Адрес элемента вычисляется сразу (`data + i`), вставка и удаление в середине сдвигают хвост.
- **Односвязный список.** Указателя на хвост и ссылок назад нет, поэтому до конца и до узла по значению идём от головы.
- **Двусвязный список.** Благодаря `head`, `tail` и `prev` всё рядом с известным узлом делается за O(1). Остаётся только O(n) на поиск узла.
- **Очередь и стек.** Работа только с концами списка — O(1).
- **АВЛ-дерево.** Высота O(log n), поворот — O(1), на пути O(log n) узлов. Обходы PRE/IN/POST — O(n), BFS по уровням — O(n·log n).

## Достоинства и недостатки

| Структура | Достоинства | Недостатки | Где применяется |
|---|---|---|---|
| Массив | доступ по индексу O(1), данные подряд в памяти | вставка и удаление в середине O(n), копирование при расширении | `vector`, буферы, таблицы, матрицы |
| Односвязный список | вставка в голову и после узла O(1), без копирования | доступ O(n), назад не пройти | цепочки в хеш-таблицах, списки свободной памяти |
| Двусвязный список | вставка и удаление у узла O(1), проход в обе стороны | две ссылки на узел, доступ O(n) | LRU-кэш, история «назад/вперёд», undo/redo |
| Очередь | O(1) на обоих концах, порядок FIFO | доступ только к голове | очередь печати, планировщик задач, BFS |
| Стек | O(1), простая реализация | доступ только к вершине | стек вызовов, отмена действий, разбор скобок, DFS |
| АВЛ-дерево | поиск, вставка и удаление O(log n); inorder даёт элементы по порядку | сложная реализация, высота в каждом узле | индексы в БД, `std::set` / `std::map`, поиск в диапазоне |

## Go

Версия на Go лежит в `struct_go/dbms`: те же команды, тот же формат `data.json`, кроме деревьев. JSON читается и пишется стандартным `encoding/json`.

```bash
cd struct_go
go build -o dbms/dbms ./dbms
./dbms/dbms --file data.json --query 'QPUSH q x'
```

В `struct_go/<имя>/` лежат демонстрационные программы для каждой структуры отдельно:

```bash
cd struct_go
go run ./massiv
go run ./spisok1
go run ./spisok2
go run ./stack
go run ./ochered
go run ./ochered1
```
